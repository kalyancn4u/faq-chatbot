1. WHAT THIS PROJECT IS
-------------------------------------------------------------------------------
A local-first Semantic FAQ Chatbot (Python 3.12, CPU-only, no GPU/cloud/LLM).
It answers questions by MEANING using:
    Streamlit UI -> Sentence-Transformers embedding -> FAISS search
                 -> SQLite (system of record) -> confidence handling -> reply
Two design laws:
    #1  SQLite is the source of truth; FAISS is a DERIVED index (rebuilt from it).
    #2  A weak match never becomes an answer (confidence bands; honest fallback).
V1 retrieves CURATED answers only; it never generates/hallucinates.

Plus: a full "code walk-through" (markdown docs + Marp HTML slide decks + a live
GitHub Pages site) and two reusable playbooks for building such walk-throughs.

3. ENVIRONMENT (IMPORTANT — non-obvious)
-------------------------------------------------------------------------------
* `python` / `python3` / `py` on PATH are Microsoft Store STUBS (they error).
  The REAL interpreter is Miniconda:  D:\tools\miniconda3\python.exe (3.12.9).
* Project dependencies live in a repo-local venv:  .venv\  (created from the
  Miniconda python). Use  .venv\Scripts\python.exe  to run app/tests.
* Do NOT use conda to install here: `conda create`/repo access fails with
  CondaSSLError (this network intercepts TLS). `pip` + PyPI WORKS.
  The base pip config has a dead extra-index-url (pypi.ngc.nvidia.com) +
  no-cache-dir=true -> harmless but slow; use `--index-url https://pypi.org/simple`.
* The same TLS interception blocks huggingface.co, so the embedding model loads
  from local cache: `.env` sets HF_OFFLINE=1 (wired via settings.py -> sets
  HF_HUB_OFFLINE/TRANSFORMERS_OFFLINE). Model all-MiniLM-L6-v2 IS already cached.
* Building the SLIDES needs Node.js (Marp CLI). Node 18/20 present; `marp`
  installed globally (v4.x). CI installs it fresh.
* Shell: PowerShell primary; Git Bash also available. Pass Python scripts as
  files (inline `-c` with quotes gets mangled through PowerShell).

-------------------------------------------------------------------------------
4. RUN THE APP
-------------------------------------------------------------------------------
    .venv\Scripts\activate
    python scripts\initialize_database.py --with-sample   # once: schema + 30 FAQs
    python scripts\rebuild_index.py                        # build FAISS index
    streamlit run app\main.py                              # open the app
Sidebar: switch Chat/Admin, pick "Reply format" (Chat/WhatsApp/Telegram/SMS),
toggle "Developer mode" for retrieval diagnostics.

-------------------------------------------------------------------------------
5. RUN THE TESTS
-------------------------------------------------------------------------------
    .venv\Scripts\python.exe -m pytest -q          # expect: 44 passed
(First run loads the real model once; ~10s thereafter with HF_OFFLINE.)

6. BUILD / PUBLISH THE SLIDE DECKS
-------------------------------------------------------------------------------
Local build (needs Node):
    scripts\build_slides.ps1        # Windows;  -Pdf also exports PDFs
    ./scripts/build_slides.sh       # macOS/Linux/CI;  --pdf for PDFs
    -> decks in build/slides/ (open walkthrough-full.html)
Publish: push to main -> .github/workflows/pages.yml rebuilds + deploys to Pages.
Pages was already enabled once (gh api ... /pages -f build_type=workflow); the
Actions token CANNOT create the Pages site, so never rely on enablement:true.

VISUAL QA WITHOUT THE BROWSER PANE (it is flaky here):
    render slides to PNG and open them, e.g.
    marp docs/walkthrough/06-*.md --images png -c .marprc.yml --no-stdin \
      --allow-local-files --theme docs/walkthrough/assets/marp-theme.css -o /tmp/png/ch.png
Overflow check: serve build/slides, in console measure
    [...document.querySelectorAll('section')].map(s=>s.scrollHeight-s.clientHeight)
    (re-run AFTER the page settles; first paint can show a phantom ~20px).

7. MARP / BUILD GOTCHAS (already handled — keep them)
-------------------------------------------------------------------------------
* .marprc.yml has `breaks: false` (else Marp turns source hard-wraps into <br>
  and footnotes/body wrap early with a right gutter). Build passes -c .marprc.yml.
* Always pass --no-stdin (Marp hangs waiting on stdin when not a TTY).
* Marp does NOT inline <img> into HTML -> build copies assets/*.svg next to decks.
* Deck is pinned light (:root{color-scheme:light}) so dark-mode viewers don't get
  dark text on a dark slide (imported theme uses light-dark()).
* Do NOT run two slide builds at once (they share temp files _build_*.md in
  docs/walkthrough and clobber each other).
* PowerShell 5.1 reads BOM-less files as ANSI -> build_slides.ps1 reads UTF-8 and
  stays ASCII-only; it judges Marp by exit code (native stderr looks fatal).
