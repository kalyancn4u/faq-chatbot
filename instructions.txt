3. ENVIRONMENT (IMPORTANT — non-obvious, not in the spec)
-------------------------------------------------------------------------------
* `python`/`python3`/`py` on PATH are Microsoft Store STUBS (they error).
  Real interpreter: Miniconda  D:\tools\miniconda3\python.exe  (3.12.9).
* Project deps live in a repo-local venv:  .venv\  (built from that Miniconda
  python). Use  .venv\Scripts\python.exe  to run app/tests.
* Do NOT use conda to install here: `conda create`/repo access fails with
  CondaSSLError (this network intercepts TLS). `pip` + PyPI WORKS.
  (Base pip config has a dead extra-index-url pypi.ngc.nvidia.com + no-cache-dir
   -> harmless but slow; add `--index-url https://pypi.org/simple` if needed.)
* Same TLS interception blocks huggingface.co, so the embedding model loads from
  local cache: `.env` has HF_OFFLINE=1 (wired via settings.py). Model
  all-MiniLM-L6-v2 is already cached.
* Building the SLIDES needs Node.js (Marp CLI, v4.x installed globally; CI
  installs it fresh). Not needed to run the app.
* Shell: PowerShell primary; Git Bash available. Pass Python scripts as FILES
  (inline `-c` with quotes gets mangled through PowerShell).

    marp docs/walkthrough/06-*.md --images png -c .marprc.yml --no-stdin \
      --allow-local-files --theme docs/walkthrough/assets/marp-theme.css -o /tmp/png/ch.png
Overflow check: serve build/slides, in the console measure
    [...document.querySelectorAll('section')].map(s=>s.scrollHeight-s.clientHeight)
    (re-run AFTER the page settles; first paint can show a phantom ~20px).

Full slide/design/publish details -> instructions_ppt.md (this repo) and
instructions_codewalk.md (portable, any repo).

7. MARP / BUILD GOTCHAS (already handled — keep them)
-------------------------------------------------------------------------------
* .marprc.yml has `breaks: false` (else Marp turns source hard-wraps into <br> ->
  footnotes/body wrap early). Build passes -c .marprc.yml.
* Always pass --no-stdin (Marp hangs on stdin when not a TTY).
* Marp does NOT inline <img> -> build copies assets/*.svg next to the decks.
* Deck pinned light (:root{color-scheme:light}) so dark-mode viewers don't get
  dark-on-dark.
* Never run two slide builds at once (they share temp files _build_*.md and
  clobber each other).
* build_slides.ps1: reads UTF-8, stays ASCII-only, judges Marp by exit code.
